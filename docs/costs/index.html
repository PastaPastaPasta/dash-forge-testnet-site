What things cost

Forge charges nothing. Nobody runs it, so nobody takes a cut. What you pay goes to two places: Dash Platform fees, paid from your identity's credits, and your own storage provider's bill, if you use one. Reading, cloning and browsing cost nothing on Platform. If a repository's packs are in a bucket, its owner's provider may bill the owner for the download traffic (egress).

Amounts are in DASH. The CLIs and web app show an optional fiat equivalent beside costs using live mainnet rates. Costs, quotes and budgets on testnet and devnets say on mainnet; balances there remain test DASH, no cash value, with no fiat equivalent. With no usable rate, amounts stay in DASH alone. The dollar amounts in the examples below are illustrative; live rates vary.

dg --fiat EUR cost estimate chooses a currency for one invocation. The CLIs resolve --fiat <CODE|off> (dg only), then DASH_FORGE_FIAT, then fiat = "EUR" in ~/.config/dash-forge/config.toml, then USD. The 34 supported fiat codes and off are case-insensitive; empty values are unset. off at any level wins: use dg --fiat off …, DASH_FORGE_FIAT=off, or fiat = "off" to disable prices and their requests. An unknown flag value is a usage error; an unknown environment or config code warns once and falls back to USD for that setting.

Rates come from CTX, with CoinGecko as the fallback (data provided by CoinGecko). Requests do not vary with your selected currency. The providers see your IP address. No account data or cookies are sent. The cache refreshes after 10 minutes, remains usable for up to 24 hours, and waits 10 minutes after a failure before retrying. A CLI invocation has a total two-second fetch budget; git-remote-dash starts its background refresh only when it receives a push command, and a push never waits for prices. Fetch and clone do not start a rate request. Costs on test networks also use these providers; their balances have no fiat equivalent. The cache is fiat-rates.json under the usual Forge cache directory (DASH_FORGE_CACHE_DIR overrides it; DASH_FORGE_NO_CACHE=1 disables disk caching).

DASH_USD=<n> supplies a fixed positive USD rate and skips both providers. It supplies only USD, so another selected currency has no fiat figure. In dg --json, the existing usd and usdPrice fields remain USD-only and mainnet-only, and are null when no rate is available or prices are off. An optional fiat object carries {currency, amount, rate, source, fetchedAt} when the selected currency has a rate. source is ctx, coingecko, or DASH_USD. fetchedAt is the local fetch time in Unix milliseconds (or the invocation time for DASH_USD); these are current price equivalents, not historical quotes.

Credits

Platform fees are paid in credits, from your identity's balance. 1 DASH = 100,000,000,000 credits.

You get credits by locking Dash into your identity from any Dash wallet: when you create the identity, or later with a top-up (the bridge's Top Up Existing Identity). Forge does not sponsor identities, and mainnet has no faucet. Testnet Dash is free test money, from the Dash testnet faucet or faucet.thepasta.org; the web app links both. Code stored on Platform adds up to about 0.39 DASH per MiB (permanent), so before a first push either add your own storage or deposit about 0.4 DASH per MiB.

dg auth balance
Identity: ExampLeidentityExampLeidentityExampLeidentEx
Balance:  0.4821 DASH (48210000000 credits)

When the balance runs out, writes fail with E401. Reads keep working, and nothing you stored is lost.

Deposits and burns

Every byte you store on Platform costs about 27,700 credits. On top of that, a document's fixed index overhead varies by type and by which index trees already exist: small testnet writes cost about 0.0002–0.0015 DASH before adding large text or binary payloads. Most of a large write is a deposit:

PartCreditsComes back?
Storage deposit27,000 per byteYes, mostly, if the document is deleted (see Refunds)
Processing~400–700 per byteNo, it is burned
Per document (its index entries)Varies by type and first-write subtreesThe refundable portion of deleted index storage can come back

The per-document fee is why a small write costs about 0.001 DASH, not the few hundred thousand credits its bytes alone would cost.

Historical rule of thumb for packs on Platform †: 1 MiB ≈ 0.33–0.36 DASH measured on devnet moutai, about 0.0046–0.0050 DASH for each 14.7 KB chunk document; dg and git push quote ~0.39 DASH/MiB, an upper bound. About 75–85% of it is the deposit.

A chunk costs a little more the more chunks the whole network holds: every chunk of every repository sits in one tree, and adding one rewrites the chunks on its path to the root (about 7M credits per level, ~1.4% of a chunk). The quote allows for a network of up to about 65,000 chunks (~1 GB of packs on Platform). The dashpay/dash import on moutai (19,107 chunks, 2026-09-28) paid about 98M credits per chunk beyond its bytes, where the old quote allowed 94M, so its estimate came in 0.6% under the charge. The quote now allows 140M.

dg cost estimate prices a first push the way git push prices it: the pack and its browse index, their two manifests, one ref update, and the history index a push to the default branch publishes. Run in a repository (or with --path <repository>), it builds the pack a push of HEAD would upload and computes the history index, as the push does, and prices them on the storage that repository's git push would use (its forge remote's dashStorage, else dash.storage, else Platform). --backend prices another, and --private prices a private repository, whose pack and indexes are stored sealed (a local clone cannot tell its visibility). In a shallow clone, where a push publishes no history index, the quote leaves it out and says why:

dg cost estimate                  # the repository in the current directory, on its own storage
dg cost estimate --backend s3     # the same repository, packs in your own bucket

With --backend s3, ipfs or https the quote is the same whatever the size: Platform bills the manifests and the ref update, never the bytes. --backend mixed keeps a copy in each place and pays for both.

--bytes <N> prices a pack of that size without a repository. It assumes one object per 512 bytes for the browse index, and on Platform it leaves out the history index's chunks, whose size depends on the repository (it says so):

The price git push quotes is an upper bound, never below the charge. On the 15 first imports of the beta.6 showcase (a whole repository each: the repository, its pack, its refs, releases and labels), the estimate was 1.08–1.16x the charge for a pack of 5 MiB or more (dashpay/dash, 259 MiB: 1.08x), and 1.08–1.27x for a 1–3 MiB one, where the per-document fees weigh more.

A deposit only comes back when the document is deleted. Some documents can never be deleted, by design (see Refunds). For those, the deposit is effectively a one-time cost.

Removal is the one that surprises organisations: its cost grows with the number of members, and every removal pays it again. Add people in batches, and remove them only when you must. Who can read what explains what each step does.

How Trending counts. Trending on Explore ranks repositories by their new stargazers in the last week (or today, which is the UTC day so far: the windows start at 00:00 UTC), read with a proof from the star's weekly window index. Every new star counts. An unstar is refunded, but the star keeps counting in the windows it was in until they pass; starring the same repository again inside one of them counts once. Explore leaves private repositories and an owner's star of their own repository out of Trending when it reads the ranking. No index gives a star's time back, so it can only take the owner's star out of a repository created inside the window (less than a week old): an owner's star of an older repository may count, by one.

Where the historical numbers come from: the per-write balance changes recorded by the push calibration (2026-09-27/28; its figures are the constants in forge_core::cost::push_fees), the web app's measured model (forge-web/lib/sdk/cost.ts), the live measurements in the pull requests that built each feature and in e2e/README.md, and the contract costs in forge-v2.md §7.

What you've actually spent. dg cost audit estimates one identity's total Forge spend — with no repository argument, every document it has created across the network, totalled by type and by repository; give it a repository (dg cost audit owner/name) for that repository's live pack-storage tally instead: its packs on Platform and the deposit their chunks lock, and apart from them the packs kept off Platform (a bucket, IPFS, or a fork's parent), which lock none. forge-v2 keeps no on-chain spend ledger, so the identity audit is (proved document count) × (that type's typical create cost, measured on devnet bonsia), with each pack's chunks priced by its size as git push prices them, the same figure shape as the web app's Settings → Spend ledger — but the two are not expected to agree: the web ledger is a per-browser history of actual balance changes (so it sees refunds, and misses writes made from any other browser or from dg itself), while this audit is a network-wide estimate at each type's flat rate (so it misses a first-of-its-kind write's or an unusually large write's true cost — see the table above). Treat both as estimates, and see above for where they can diverge. --owner takes an identity id or a DPNS name and defaults to the signing identity; --since takes a duration (24h, 7d, 2w, 1y) or an absolute date (2026-01-01); neither combines with the repository argument. Its repository scope has one gap: a membership revoked with no other trace left in that repo (no issue/patch filed, no still-registered CI runner, and — in a public repo — no repoKey) cannot be found by any proved query; the command's own output says so. chunk counts also come from each owned pack's own packManifest rather than being queried directly, so a chunk uploaded by a push that never finished with a manifest (interrupted, or a mid-push membership revocation) is not counted either — the output notes this gap too. On a network with RC2's fused star (the three-contract devnet set) there is no starBeat to count (it isn't queried), and each star is priced at the fused star's ~46 M credits (a registration fee probe, not yet a measured charge).

History index

The file list's last-commit column, the exact n commits count, and the file versions Blame and a file's History read come from a history index the push publishes with the default branch (design). Without one, the web walks history in your browser: 400 commits at a time for the column, and every commit back to a file's first version for Blame. The first index is a full one. Later pushes publish a small delta over it. Each delta covers every change since the full index, so each push pays for all of them again. Once the deltas over a full index have cost as much as the full index itself, the next push publishes a full one again. A delta is never over half the full index.

Since v2, the index lists each path's newest 256 first-parent versions: the commit, author and blob of each. Blame of dashpay/dash's src/clientversion.h then needs 16 chunk queries instead of 357 (the offline replay in the design). The lists make the index about ten times larger than v1.

A push that stores no new pack, such as a retry of a recorded one, publishes none; dg repo reindex fills that in.

Why a repository is cheap. Every repository lives in a few shared contracts (forge-core, forge-collab, forge-community and, on the production set, forge-meta), registered once per network by the deployer, not by you: 1.873 DASH for the four on testnet (2026-10-26) (Deploying Forge to a network). A new repository is then just three documents. The first version of Forge gave each repository its own contract, and contract registration fees made that cost about 1.18 DASH per repository; it was removed on 2026-09-26.

Packs are git packfiles: delta-compressed and deflated, typically 20–35% of the size of a checkout. Forge never stores raw files.

Passkeys for other devices

A passkey's entry is one small stored item, written with this browser's key (so it comes out of that key's budget, like any write). Measured on testnet with the live test (lib/auth/passkey-vault.live.test.ts), which prints what each step costs.

At most 10 passkeys per identity. An entry is always the same size, whatever keys it holds.

Boards

A board's definition is one document per member who edits it, and a card one document per member, item and board, replaced in place by every later change (boards design). Measured on testnet (2026-10-27, on the scratch set and the live set) with the live test (lib/repo/boards.live.test.ts), which prints what each write costs.

Platform or your own bucket

Pack bytes are almost all of a repository's size, so where you keep them decides the cost:

Where packs liveYou payFor a 50 MiB repository with 10 pushes a month
Your bucket (any S3-compatible store) or IPFSPlatform: manifests + refs per push. Provider: storage and egress, at their prices.~0.04 DASH a month on Platform (~0.004–0.0055 DASH a push to the default branch, its history index included), plus your provider's prices, if any
Dash Platform~0.33 DASH per MiB pushed (quoted up to 0.39), plus ~0.004–0.011 DASH per push~17 DASH for the first upload, then ~0.33 DASH per MiB pushed

Platform storage buys you something: it is stored by the network, and it can never be deleted, even by you. Your bucket is cheap, but it is only as available as your account with the provider. You can have both: dg storage use nas,platform keeps a copy in each place. See Bring your own storage.

If you set nothing, packs go to Platform. That is fine for small repositories, and expensive for large ones.

Refunds

When a document is deleted, Platform refunds the part of its storage deposit that has not been used yet. Platform spreads the deposit over 2,000 epochs, so how long a refund lasts depends on the network's epoch length (table below). The burned part never comes back. Only the identity that paid can get the refund, and only by deleting its own documents.

NetworkEpochThe deposit is spread overDelete a document after……and get back about
Mainnetabout 9 daysabout 50 yearsweeks or monthsnearly all of the deposit
Testnet1 hourabout 83 days1 day / 7 days / 14 days / 30 days / 60 days97 % / 80 % / 64 % / 36 % / 7 % (nothing after about 83 days)
Devnetsset per devnet2,000 of its epochsdepends on the devnetdepends on the devnet

On testnet, a document deleted after a few weeks returns only part of its deposit, and after about 83 days none. The web app says "refunds about X if deleted soon; less as it ages": X is a conservative approximation from immediate-delete measurements, not an upper or lower bound. An older document may refund zero. The percentages come from Platform's fee distribution table (FEE_DISTRIBUTION_TABLE in rs-dpp), not from a Forge measurement.

What can be deleted, and so refunded:

Deletable?
Pack chunks and manifestsNo. Platform-tier storage is permanent, so that nobody can break a repository by deleting what others depend on. dg repack consolidates into a new pack and deletes nothing on Platform.
Issues, PRsNo, so that threads cannot be rewritten
Ref updates, config, eventsNo, never (they are the audit trail)
The repo documentNo
Membership documents (writer, maintainer)Yes, by the owner (that is how a collaborator is removed)
Comments, reviews, labels, webhooks, stars, follows, your profileYes, by the author
Release revisionsNo. Release revisions are permanent; unpublish appends another revision

There is no dg repo delete: a repository cannot be deleted.

The audit trail grows forever: each ref update costs about 0.0006–0.0009 DASH and never comes back, about 0.6–0.9 DASH per 1,000 pushes. That is the price of a history nobody can rewind.

Seeing costs before you pay

  • dg asks first. Every command that writes asks before it writes ([y/N]; dg init and dg repo create ask Proceed? [Y/n] after showing the price) unless you pass --yes. dg repo create, dg repack and dg repo reindex show their price before the question. For other commands, use dg cost estimate before you write (in a repository it quotes a first push of it to --backend platform, s3, ipfs, https or mixed) and dg cost prices / dg cost audit to see the reference table or what you've already spent. With --json or no terminal, dg refuses to write without --yes (E802).
  • git push prints its estimate before it writes to Platform, and what Platform actually charged when it is done. The estimate prices every write as the first of its kind, so it is an upper bound: 1.08–1.27x the charge on a first import of 1 MiB or more, up to about 1.6x on a tiny first push and 1.85x on a small later one. It asks before spending more than 0.05 DASH by default, and before storing more than 1 MiB on Platform when dash.storage is unset (Platform packs are permanent). To change that:
    git config --global dash.costWarnThreshold 0.1    # ask above 0.1 DASH (default 0.05; `off` disables the threshold)
git config --global dash.confirm auto             # auto | always | never | refuse

    Without a terminal (CI), a push over the threshold stops with E801 rather than spending. Before it uploads anything, a push also checks that your balance and your key's remaining budget cover the estimate (E401 / E402); a push resumed after an interruption quotes only the chunks left.

  • forge-import --dry-run estimates a whole GitHub import, and --max-spend caps it. Without --max-spend, a run is capped at the estimate it shows you.
  • dg init and dg repo create stop before creating anything when no storage is chosen, and quote what Platform storage would cost for this repository (E508).
  • The web app shows the price on every button that signs (repository, issue, comment, state change, review, member, star, release, key top-up), with refunds for deletes. After each write a toast shows the actual balance change. Settings → Spend keeps a local ledger in this browser: month and all-time totals by repository, and estimates that missed by more than 25 %.
  • Limited keys cap spending. A browser key can spend at most its budget (0.05 DASH by default), and a CI runner key its own (0.5 DASH). Platform enforces the budget at consensus, whatever the software does. See Identity and keys.
  • The Mirror Action has a per-run cost-cap (0.05 DASH by default) and reports what each run spent in the job summary.
  • dg cost audit totals what an identity has spent on Forge, from proved document counts (not a local ledger — see above); --since narrows the window, --json for scripting.

Prices in the web app

Settings → Prices chooses the currency shown beside DASH costs and can turn prices off. Rates come from CTX (rates.ctx.com), with CoinGecko (api.coingecko.com) as a fallback. The app caches rates for 10 minutes and can use them for up to 24 hours while offline; without an available rate it shows DASH alone. Providers see your IP address, standard browser headers and that the request comes from this site. Turning prices off stops rate requests. On test networks, costs say “on mainnet”; free test balances have no cash value and get no fiat figure. Settings → Spend values use today's price, rather than the price when the write happened.

The CLIs use the same live mainnet rates, with the settings, cache and opt-out described above. Rates have no refresh timer: an idle page rechecks expiry when rendered or made visible again; the “updated” age changes on render.
