FAQ

Who hosts Dash Forge?

Nobody. There is no Forge server, company account or database.

  • Refs, issues, PRs, reviews and access control are documents on Dash Platform, a network run by Dash masternodes. Each document is signed by its author's identity.
  • Pack bytes (the git objects) are stored wherever the repository's owner puts them: their own S3-compatible bucket, an IPFS node, or Platform itself.
  • The web app is a static site. It is served from GitHub Pages at forge.dashhq.org (mainnet) and testnet-forge.dashhq.org (testnet), and anyone can build it and serve it elsewhere.
  • The CLI (dg, git-remote-dash) talks to Platform nodes and storage directly.

The Forge project publishes code and nothing else. Anything that looks hosted is either a static file or something you run yourself.

Can my repository be taken down?

Not at the protocol level. The Forge contracts are registered without Platform's contract moderation, so nobody can delete your documents or ban your identity. That includes the Forge project, Dash Core Group, and the masternode operators. Ref history can't be deleted even by you, so nobody can rewind a branch.

What someone can do:

  • Your storage provider can delete your bucket. Refs and history metadata survive on Platform, but the bytes in that bucket go. Protect against this with a second copy (dg storage use r2-main,kubo), with Platform storage for packs that must outlive every bucket, and with dg reseed --from-local, which restores a lost copy from any clone. See Bring your own storage.
  • GitHub, a domain registrar or Cloudflare can take down forge.dashhq.org. The repositories are not there, so they are unaffected. See the next question.
  • A government can block access to Platform nodes or gateways in a country. That is a network problem, not a takedown. The data is still there, and reachable from anywhere else.

Is there any moderation?

Not at the protocol level. On mainnet, spam and abuse cost the sender real fees, which is the only floor; on a test network DASH is free, so fees are no floor there. Clients can still choose what to show: an issue's or PR's state counts only changes made by its author or by the repository's members, and anyone can build a client that filters more. No one can delete another person's documents.

The site dashhq hosts does this too: it can leave a repository or identity out of its lists, and show "Not shown on this site" in place of a hidden repository's pages and a hidden identity's repositories and profile details. The data stays on Platform, dash:// still works, and other builds still show it. Hosted curation says how an entry is requested and added.

What if forge.dashhq.org disappears?

Nothing is lost. Your repositories live on Platform and in your storage, not on the website.

  • git clone dash://…, git push and every dg command keep working. They never touch the website.
  • The web app is a static build of forge-web/. Build it and serve it from anywhere, including IPFS: see Run your own copy of the web app.

Do I have to trust the website, or Platform nodes?

Mostly not. Every Platform read is checked against a proof, and every byte is checked against its hash. Two things are still trusted. First, the HTTPS endpoint that supplies the validator quorum keys proofs are checked against; the web app compares those keys with a second source (Platform nodes themselves) on every repository page and says Failed if they disagree. Second, the code doing the checking: the web app's checks protect you only if the JavaScript you loaded is the real app, so if you don't trust forge.dashhq.org (GitHub Pages), build the app yourself from source you have read and serve it, or use the CLI, which needs no website. Verify Forge explains the Verification card, and shows how to cross-check the keys against your own Dash node.

Does the website track me?

forge.dashhq.org counts visits with Cloudflare Web Analytics: page views, the referrer, the browser, the country and load times. Cloudflare says it uses no cookies or local storage and does not fingerprint visitors. The script is pinned by its hash, and the app works the same if you block it. Builds you run yourself have none unless you set NEXT_PUBLIC_CF_BEACON_TOKEN, and the IPFS release never has any. See Hosting §6.

Who pays for it?

You, directly, and only for what you write. Platform fees come from your identity's credits. Storage bills come from your own provider, if you use one. Reading and cloning are free. Nobody sponsors identities. See Costs.

How much does it cost?

Measured on testnet: creating a repository costs about 0.0024 DASH. A push to your own bucket costs about 0.004–0.0055 DASH. An issue costs about 0.0012 DASH, and a fork of a small repository about 0.008 DASH. Storing packs on Platform costs up to about 0.39 DASH per MiB. Mainnet charges the same amounts in real Dash. The full table is in Costs.

Is it on mainnet?

Yes, since 2026-11-24, at forge.dashhq.org.

dg doctor shows which network you are on, its protocol version, and whether forge-v2 is deployed there.

Can I have private repositories?

Yes: dg repo create --private (or dg init --private), and New → Repository → Private in the web app. Contents are encrypted in the client with a per-repository key that only members hold, and branch names, issues, PRs, comments and reviews are encrypted too. Anyone can still see that the repository exists, its name, its members, its size and when it changes. Forks and webhooks are refused on private repositories, because they would publish content unencrypted (E207). Releases are supported and sealed: a private repository's release notes and asset list are encrypted, and so is every asset file Forge seals, in the web app and in dg release create, unpublish and download. The one exception is an imported asset that could not be fetched and sealed: it stays an external link, whose URL is hidden but whose file is not encrypted, so anyone who can reach its source can read it. Label definitions are allowed but stay public. Removing a member rotates the key for future content, but cannot take back what they could already read. Collaborating lists exactly what is hidden and what is not; the design is in private-repos.md and forge-v2.md §5.

How does this relate to GitHub?

Forge is not a GitHub clone, and it does not need you to leave GitHub.

  • The commands are familiar. dg is shaped like gh, and git itself is unchanged: git clone dash://…, git push, branches, tags. jj push and fetch work too; see the quick start for the one setup step that differs.
  • You can mirror. Keep working on GitHub, and keep an unkillable mirror on Forge. The Mirror Action keeps code, issues, PRs, releases and labels in sync on every GitHub event.
  • CI can listen. dg webhook add and a relay you run deliver GitHub-shaped webhooks, so existing CI receivers work (Collaborating).
  • It is not at feature parity. No hosted CI (bring your own: forge-runner runs GitHub Actions workflows on your machine and reports checks with a runner key), and no wiki, discussions or global search; organizations are on testnet only. No https:// clone URLs (that would need a server); the web app offers a zip download instead. No shallow clones: use git clone --filter=blob:none instead. The web app opens, reviews and merges PRs and forks repositories, but some merges still need dg: changes both sides made to the same files, a private repository, a merge too large to build in the browser, and a history that changes .gitmodules or .gitattributes or holds an object git would reject. See Collaborating. Moving from GitHub or GitLab lists what has no equivalent, and the workarounds.

Can I use a username instead of the long identity id?

Yes: register a DPNS username in the web app (Settings → Choose a username), with dg auth name register <label>, or in the Dash bridge. Then forge.dashhq.org/alice/project, @alice in the web header's jump box, git clone dash://alice/project and dg … alice/project all resolve it, with a proof-verified DPNS read. dg repo list --owner and granting access (dg collab add) still take the identity id.

I lost my laptop. Is my code gone?

No. Your repositories are on Platform and in your storage. Your identity survives as long as you have its 12 words or a backup of the identity file. A browser key on the lost laptop can spend at most its remaining budget, only on Forge, until it expires; revoke it from another device to stop it sooner. See Backup and recovery.

I lost my 12 words and my identity file.

Then that identity is gone. Nobody can recover it, and nobody can sign as it again. Everything it published stays readable and clonable. Its repositories can no longer gain or lose members, because only the owner can change membership. Members it already added can keep pushing. To carry on under a new identity, create a new repository and push your clone to it. Keep the words safe.

Which browsers does the web app support?

Chrome and Edge 103 or newer, Firefox 104 or newer, and Safari 16 or newer (macOS and iOS). That floor comes from what the app needs to run at all: WebAssembly under a strict content policy (wasm-unsafe-eval), IndexedDB, WebCrypto, AbortSignal.timeout and Array.prototype.findLast. It is declared as the browserslist in forge-web/package.json, which the build compiles for.

Protecting the browser vault with a passkey also needs WebAuthn's PRF extension, which depends on the browser (Chrome and Edge 116, Safari 18, recent Firefox), the operating system and the passkey provider (iCloud Keychain and Google Password Manager support it; some third-party managers and security keys do not). Where it is missing, use a passphrase instead; everything else works the same.

How do I run my own IPFS node?

Run dg ipfs up. It downloads kubo (checked against a hash built into dg), runs it for your user, starts it at login, saves a storage profile called kubo, and prints a link and a code that connect the web app. Then dg storage use kubo sends your pushes there. It costs no DASH. Your node stores the bytes on your own disk. The node accepts the web app only from the websites you allow, with a token that can add, pin and unpin and nothing else. Run your own IPFS node has the details, including port forwarding so others can reach it.

How do I keep a copy of someone's repo?

Pin it to your IPFS node: dg ipfs pin owner/name, or press Pin on the repository's page. Add --follow and your node pins new pushes too, every 30 minutes. It pins the files that the repository's owner, maintainers, writers and bots recorded, checks each against its hash, and costs 0 DASH, since nothing is written to Platform. Your node tells the IPFS network that it holds the files, so your IP address is linked to the repository. For a private repository you must be a member and agree to that first. --dry-run shows the size before you pin. See Pin someone else's repo.

Why does Safari not connect to my node?

Safari doesn't let a secure site (https://forge.dashhq.org) talk to a node on your own computer, and the web app can't work around that. The page tells you so. Use dg to push to your node, or connect from Chrome, Firefox or Brave: they ask you to allow the site to reach apps on your device. See Connect the web app.

Where do I report a bug?

GitHub Issues for now. Every error dg prints has a code; errors.md explains each one.
